# SEC observed financial lifecycle bundle v1

- Goal: persist and restart the [observed system replay](sec-observed-system-replay.md) lifecycle without changing existing producer bytes, identities, row semantics, or public availability; local observations and caller-attested quality/commits remain unauthenticated local evidence.
- Files: add `observed_financial_bundle.py` and focused private helpers if needed; refactor `observed_xbrl_financials.py` only to share its complete offline build/validation path; narrowly correct observed selector policy filtering as below; exports, synthetic offline tests, and linked documentation/changelog accompany implementation. Legacy PIT bundle/query types remain separate.
- API: `write_sec_observed_financial_bundle(*, store, batch_identity, productions, quality_records, consumer_commits, captured_at, resolve_observation, limits...) -> SnapshotRef`; `load_sec_observed_financial_bundle(*, store, bundle_ref, resolve_observation, limits...) -> SecObservedFinancialBundle`. Resolver is `Callable[[str], tuple[SnapshotStore, SnapshotObservationRef]]`, keyed by observation identity; it supplies caller-owned storage locations, never paths from JSON.
- Result: frozen `SecObservedFinancialBundle(batch_identity, productions, quality_records, consumer_commits, captured_at)` contains deterministic identity-sorted tuples usable directly by the observed selector. That selector ignores commits whose supplied quality record binds the same production but a different policy; genuinely missing quality, cross-production bindings, and selected-policy future-quality/timing failures still fail explicitly under existing visibility rules. `batch_identity` is a nonempty string, `captured_at` is aware UTC and at least every production/observation/quality/commit time; capture is persistence metadata, never eligibility evidence.
- Envelope: canonical UTF-8 JSON, schema/serialization `sec-observed-financial-bundle-v1`, exact top fields `schema`, `batch_identity`, `captured_at`, `productions`, `quality_records`, `consumer_commits`; reject duplicate keys, unknown/missing fields, wrong exact scalar/container types, nonfinite numbers, malformed identities/timestamps, and noncanonical bytes. Request is exactly provider `sec`, endpoint `observed-financial-bundle`, parameters `{"batch_identity": batch_identity}`, empty fields, mode FROZEN; capture in payload must equal replayed manifest time.
- Production entry: exact fields `production_identity`, `request`, `produced_at`, `source_receipt`, `package_receipt`, `output_receipt`; request retains exactly the existing producer request payload fields. Each receipt contains every existing `receipt_binding` field except `path`: observation_identity, snapshot_identity, fact_version, mode, provider, endpoint, request_identity, response_sha256, serialization_identifier, snapshot_fetched_at. Resolver receipt must match every field, and SnapshotStore replay must validate request, serialization and bytes; cache only by exact observation identity and reject conflicting claims.
- Lifecycle entries: persist every constructor field plus derived `quality_record_id`/`commit_id` using the existing record names and UTC timestamps; reconstruct via public constructors and require exact recomputed identities. Deduplicate exact logical entries by identity, reject conflicting identities, and sort canonically; production equality for this purpose uses complete path-free entries, so relocated stores do not change identity. Count raw inputs before deduplication.
- Restoration: share the producer's full source/package replay, header/package binding, causal checks, component/XML bounds, pinned parser, row validation and canonical result serialization; replay retained output and require byte-for-byte equality with rebuilt output before the producer module alone issues existing private evidence/production seals bound to resolved receipts. No output-only decoder, copied capability, bypass sink, temporary output store, or loader filesystem write; unavailable/mismatched parser fails explicitly.
- Writer validation: revalidate supplied seals without mutating caller objects, reconstruct every production through the same retained-source/output path as load, and require equality of complete canonical output/production identity. Resolve/replay all dependencies and validate the entire lifecycle before the sole final bundle write; no partial returned bundle or writes on any input, parser, dependency, graph, capture, or size failure.
- Graph: for every production and every supplied quality policy, require a complete strictly chronological chain starting PASS/QUARANTINED without predecessor, each successor referencing its immediate predecessor; reject orphan/cross-policy/cross-production predecessor, forks, cycles, same-time conflicts and quality before production. For every dataset, every commit must reference an included PASS quality for its exact production with committed_at >= recorded_at >= produced_at; reject orphan/wrong bindings and distinct same-time commits per production/quality/dataset. Validate all histories, including future or unselected policies/datasets, independently of any query cutoff.
- Bounds: stricter-only positive exact integer limits `max_productions=10`, `max_quality_records=10000`, `max_commits=10000`, `max_rows=100000`, `max_bundle_bytes=8 MiB`, `max_dependency_bytes=32 MiB`; each unique source/package/output payload is at most 8 MiB and counts once against aggregate dependency bytes. Preserve producer per-production component/XML/10000-row caps; enforce count/byte budgets incrementally before additional parsing or aggregate retention, including generators and duplicate inputs.
- Storage: use existing atomic immutable `SnapshotStore.write`; identical batch/content/capture is idempotent, changed content or capture for an existing frozen batch fails without replacing it. Replay validates bundle receipt, manifest, request, mode, serialization and canonical bytes before dependency work. Existing snapshot integrity/atomicity remains the storage authority; bundle hashes do not establish external authenticity.
- Acceptance matrix: denied-network real-parser restart tests must demonstrate canonical output/production/quality/commit identities and selector result parity at before/equal/after cutoffs, both observation orders, quarantine/revocation/re-PASS and multiple policies/datasets including two policies for the same dataset, relocation, empty bundle and deterministic duplicate/order handling; selector regression tests retain missing/cross-production/future-quality failures and bundle tests reject invalid histories even in unselected policies. Retain an unchanged observed-output golden and legacy identity regression evidence.
- Failure matrix / stop: test missing/substituted/tampered source, package, output, receipt, envelope and derived IDs; all-policy/all-dataset orphan/chain/time failures, capture mismatch, type/schema/canonical failures, every count/byte boundary (including aggregate and generators), frozen collision/idempotency, interruption/concurrent writes and zero writes on writer failure or any loader path. Stop on new semantic ambiguity, parser drift or unavailable required evidence; no network, consumer migration, release/publication or availability promotion. Independent actual-diff review is required; consumer reruns are unnecessary absent consumer changes.
