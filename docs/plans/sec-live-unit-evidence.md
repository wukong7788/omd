# SEC live financial unit evidence v2

- Goal/files: correct new built-in live financial units using the filing's raw instance; scope is `edgartools_adapter.py`, additive `_statement_parser.py` boundary, focused private instance/evidence helpers, `http.py` XML support, financial models/dataset, CLI request selection, tests and migration docs. Reuse the fixed raw-unit decoder and edgartools 5.56.0; preserve observed/offline versions and unrelated edits.
- Version API: add keyword-only `parser_version` to `SecFinancialsRequest`, default `sec-live-financial-parser-v2-edgartools-5.56.0`, accepting only it and `sec-live-financial-parser-v1-edgartools-5.56.0`. V1 executes the original live path and has no unit evidence. Validate before fetching. Expose the same explicit choice in the financials CLI without changing configuration discovery or credentials; never fall back from v2 to v1.
- Standalone compatibility: `parse_statement_rows` keeps its existing default behavior; add keyword-only `parser_version` with the live-v1 default and `raw_instance: bytes | None = None`. Explicit v2 requires native `Statement` plus raw bytes, validates before native row extraction, and has no display/structured fallback. Reject raw bytes with v1 and unknown versions; existing private producer calls remain v1 by default and byte-identical.
- Acquisition: the built-in v2 client selects exactly one original XML instance using `XBRLAttachments` attachment classification, explicitly rejecting multiple distinct candidates instead of its last-wins behavior. Use original filing attachments, then at most its same-accession homepage attachments when absent. Require a safe basename and an SEC archive URL whose numeric CIK and accession directory match the selected filing; validate every redirect against that same directory. Do not infer units from names or follow arbitrary attachment URLs.
- Transport: use already available `sgml_document.content` when present, otherwise an injected `SecHttpClient` supplied through a keyword-only client argument. Never invoke network-backed `Attachment.content`. Add narrowly selected XML MIME acceptance (`application/xml`, `text/xml`, `application/octet-stream`), preserving existing JSON/ZIP behavior. Read at most 64 KiB per call, enforce 2 MiB instance bytes before parsing, and always close. Reuse existing classified retries, limiter, opener/clock/sleep injection and SEC URL restrictions; deterministic unit/source validation is not retried. These caps cover the new instance acquisition, not existing upstream filing/report fetching, and imply no hard whole-request timeout.
- Binding: before applying units, corroborate each retained native fact against a separately parsed copy of those exact instance bytes using the pinned parser: normalized concept, context reference, unit reference, Decimal value, native decimals, context period and dimensions must match. Index once; identical duplicates are permitted, missing or conflicting matches fail. This checks internal correspondence, not independent financial correctness. Reject wrong filing CIK in retained fact contexts; accession identity comes from the selected filing/attachment location, never an observation timestamp.
- Units/errors: validate the complete raw unit table before native extraction; retain decoder byte/element/depth, namespace, DTD/entity and grammar limits. Replace only `unit` by exact `unit_ref`; compound currency recomputes to None and all other row fields remain unchanged. Export `SecUnitEvidenceError`, a `SecStatementParseError` subtype, for missing/ambiguous/source-mismatched/malformed evidence. Explicitly rethrow it before broad per-statement catches so the entire call fails without a partial result or dataset writes. Custom full runners under v2 must return v2-evidenced vintages; explicit v1 preserves the legacy runner boundary.
- Evidence type: add frozen `SecFinancialUnitEvidence` with `parser_version`, canonical zero-stripped decimal `cik`, canonical dashed `accession_number`, safe `instance_document`, `instance_sha256` (64 lowercase hex), and derived `evidence_identity`. Its canonical payload has those first five fields plus `schema_version="sec-financial-unit-evidence-v1"`; identity is SHA-256 of compact UTF-8 sorted-key JSON. Validate exact versions, identifiers and digest syntax at construction. Store no raw bytes, local paths, credentials, fetch time or authenticated-source assertion; repeated identical bytes from the same filing/document yield identical evidence.
- Vintage identity: append keyword-only optional `unit_evidence=None` to `SecCompanyFinancialVintage`; bind its CIK/accession to the vintage. None retains the complete historical v3 identity formula exactly. Evidence selects `sec-company-financials-v4`, includes its canonical payload and derived identity in the existing identity payload, and exposes the evidence in serialization. Do not globally change the v3 identity constant or relabel historical/offline vintages. This evidence is caller-constructible metadata, not an authenticity seal, public availability, quality PASS or commit.
- Dataset dispatch: retain exact v3 schema/profile, tables, manifest and validation for partitions containing only legacy vintages. Any evidenced vintage selects `sec-company-financials-v4` / `sec-financials-parquet-v4`; v4 adds nullable evidence payload and identity to vintage rows and mandatory `vintage_identity` to statement rows. Mixed legacy/v2 vintages retain their own identities; validate each statement's vintage link, symbol/accession, row count and reconstructed vintage identity, evidence digest/filing binding and known schema/profile. Reject orphan/conflicting links and tampering even with recomputed file hashes. Existing immutable roots never migrate or overwrite; changed content requires a new caller-selected root.
- Migration: new default live v2 results require the v4-capable writer/validator; older validators may reject v4 explicitly. Document v1 request/CLI selection for exact legacy reproduction and the known denominator loss it retains. Dataset evidence records which instance was used but does not retain raw source or promise source replay; no hidden refetch during validation. Existing availability anchors, quality flags and missing-statement policy are otherwise unchanged.
- Acceptance—compatibility: frozen synthetic v3 vintage identity, both Parquet files and manifest remain byte-identical; all existing observed/offline v1/v2 tests remain green. Test live explicit v1 and standalone no-keyword legacy parity; live default v2 divide/product/simple units and every unchanged row field, compound currency, unknown versions, explicit standalone v2, and runner version enforcement with provider-boundary fixtures and the actual parser.
- Acceptance—failure/bounds: cover absent/ambiguous instance, wrong CIK/accession/redirect, raw/native mismatch, malformed-unused/duplicate/missing-reference units, exact/over byte limits, chunked reads and closure, MIME rejection, transient retry versus permanent failure, and one valid statement followed by evidence failure yielding no result/write. Reuse decoder grammar/security tests; all automated tests deny network. No unbounded attachment network read or upstream monkeypatch is permitted.
- Acceptance—persistence/evidence: test v4-only and same-accession mixed v1/v2 partitions, deterministic repeats, immutable collision, evidence/link/count/identity tampering with hash-correct manifests, and unchanged v3 validation. Root captures v3 golden before implementation; independent actual-diff review plus targeted static/tests and dataset artifact inspection are required. A retained real instance may corroborate corrected units offline; do not claim a completed live fetch, consumer rerun, financial PASS or full coverage from that probe.
- Stop: stop for inability to obtain/bind original instance evidence without fallback, changing old identities or availability semantics, or broadening transport/consumer permissions. Do not edit consumers, bump dependencies, publish, or invent raw facts. Assess consumer migration/rerun needs for adoption; an SDK implementation does not by itself establish downstream parity.
