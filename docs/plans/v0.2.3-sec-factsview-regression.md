# OMD 0.2.3 SEC FactsView 兼容性回归

状态：本地修复及固定申报离线回放已验收，尚未发布。2026-09-09 最初在消费者安装的
PyPI wheel 上复现；下文保留原始交接证据，当前验收结果见末节。

## 已确认问题（P0）

环境：Python 3.12、ohmydata 0.2.3、edgartools 5.56.0、yfinance 1.7.0。
真实 SEC 返回可解析的报表，但 OMD 三份申报均输出零财务行。

| 标的 | 表单 | 实际选中 accession | 财务行数 |
| --- | --- | --- | ---: |
| SNOW | 10-Q | 0001640147-26-000037 | 0 |
| NET | 10-Q | 0001477333-26-000054 | 0 |
| NET | 10-K | 0001477333-26-000016 | 0 |

请求均为 `limit=1, include_amendments=False, include_dimensions=False`。
NET 已正确选中原始年报，说明此次申报筛选通过；不能把零行解释为缺少公告。
客户端返回 `BALANCE_SHEET_PARSE_FAILED`、`INCOME_STATEMENT_PARSE_FAILED`、
`CASH_FLOW_PARSE_FAILED`、`NO_FINANCIAL_STATEMENTS`。这些是失败状态，不是有效财务覆盖。
三次调用分别约 2.81、1.67、0.70 秒；可能命中 Edgar 缓存，不代表冷下载性能。

## 根因证据

直接对真实 SNOW Statement 调用 `parse_statement_rows`，异常链为：

```text
_statement_parser.py:366 parse_statement_rows
_statement_parser.py:240 _native_statement_rows
_statement_parser.py:99 _native_index
    for fact in xbrl.facts.values():
AttributeError: 'FactsView' object has no attribute 'values'
SecStatementParseError: invalid financial statement structure
```

`xbrl.facts` 是 Edgar 的 `FactsView`，并不是 dict。现有 mock 未准确模拟此运行时形状。
同一真实 Statement 的 `to_dataframe(standard=True, include_unit=True)` 成功，
且显示的 SNOW 单季营收及营业利润与消费者此前保存的同 accession SEC 证据一致。
因此至少此项失败来自 OMD 原生事实适配，不是 SEC 没有数据。

## 最小复现

在已显式设置 SEC identity 的环境中执行；身份由调用者注入，不写入 fixture 或日志：

```python
from edgar import Company
from ohmydata.providers.sec.edgartools_adapter import parse_statement_rows

filings = Company("SNOW").get_filings(form="10-Q", amendments=False)
filing = next(f for f in filings if f.accession_number == "0001640147-26-000037")
statement = filing.obj().financials.income_statement()
parse_statement_rows(statement, "income_statement", include_dimensions=False)
```

真实调用需要实施任务授权；离线回归先用合成的 FactsView 形状对象复现。

## 后续修复契约：原生重复数值精度（2026-09-09）

状态：READY_FOR_EXECUTION。FactsView 接口修复后的受控诊断确认，NET 剩余三张
报表失败均来自 `conflicting native facts for period and dimensions`。
同 concept/context/unit 的数值在正文和报表中以不同 decimals 重复披露，现有字符串
完全相等检查误拒绝一致的舍入值。三份固定申报已保存本地、忽略跟踪的回放材料；
原失败证据保留。此节由主代理审阅冻结，Luna 实施，独立审阅后由主代理验收。

授权范围：`_statement_parser.py`、必要的同目录私有重复事实辅助模块、对应 SEC
合成回归测试、`docs/financial-period-integrity.md`、`CHANGELOG.md`。
本计划由主代理维护。已有 FactsView、客户端错误处理、测试和文档修改全部保留。
禁止依赖升级、版本变更、消费者修改、提交或发布。无需更改模型或代理配置。

数值契约依据 [XBRL OIM 6.2.1](https://www.xbrl.org/Specification/oim/REC-2021-10-13/oim-REC-2021-10-13.html)：

- 现有 concept、期间、维度分组及 unit_ref 不冲突约束不变；不引入跨单位合并。
- 相同 precision 的数值必须精确相等（Decimal 数值比较，允许等值词法差异）。
  不同 precision 必须使全组闭区间存在共同交集；不能只比较相邻数值或默认选择第一个。
  finite decimals=d 的区间为 value ± 0.5×10^(-d)，INF 为单点。
- 检查使用精确算术，不使用 numeric_value、float 或默认 Decimal 精度导致的舍入。
  缺失精度不得推断；保持完全相同且缺失精度的旧路径可用，无法证明一致则报错。
  非数值、非法精度、非有限值、同精度不同值或区间不交继续明确失败。
- 全组一致后，对每个原始 context_ref 独立选取最高精度的原始 Fact（INF 最高），
  保留该 Fact 自身 value_native、decimals_native、unit_ref 和 context_ref。
  不把一个 context 的精确值复制到另一 context。相同精度等值的词法形式选择须确定性。
- 相同 context 的一致重复只产出一行；不同 context 继续分别产出。
  Q2/YTD、维度、时点、缺失单位、PIT 语义不变；展示 DataFrame 不作为回退。
- 这是显式、文档化的重复事实选择规则，输出仍为真实披露值，不计算新金额。
  回放证据保留所有候选；消费者需重跑受影响申报，旧数据不能被称为已修复。

实施顺序：合成真实 XBRL/FactsView/Statement 边界先红，再修复重复事实处理；
随后离线回放固定三份申报，三类报表完整且各输出金额/context/unit/precision 可回溯
到采集事实，Q2/YTD 分开。诊断采集已完成，不自动重复 live。
合成测试必须覆盖正负数、零、等值词法、INF、缺失/非法 decimals、同精度真冲突、
全组不相交、单位冲突、跨 context 原生值保留、顺序无关、长 Decimal 精度及现有维度/期间测试。

资源边界：每张报表继续对 F 个源事实单遍索引；重复组线性检查和按 context 选择，
总复杂度保持 O(F + V log V)，存储 O(F)，无笛卡尔积或网络。回放限九张已捕获报表、
串行且单个命令 60 秒；保留现有单遍结构测试。异常或真实冲突必须停止该报表验收。
独立审阅补充的算术资源上限：在构造精度区间或 Fraction 前，finite decimals 的绝对值、
Decimal 原始指数的绝对值、Decimal 系数位数各不得超过 10000；超限必须抛出明确的
SecStatementParseError，不得分配超大幂、舍入或截断。此上限是公开文档化的适配器资源
约束，不是数值修正；增加超限及边界回归，普通金额/精度语义不变。
门禁：红绿回归、全 SEC 测试、全离线测试、Ruff/format/ty/build/diff、Python 3.11/3.12，
检查候选 wheel 并在隔离安装中回放；独立审阅。不得把采集成功当作财务验收成功。
