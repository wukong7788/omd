# SEC observed financial in-memory system replay v1

- Goal: select all eligible producer-validated observed financial packages at an explicit system cutoff; local known-by never becomes public availability or MARKET_KNOWN eligibility.
- Files: seal `observed_xbrl_financials.py`; add one focused observed replay module, exports, offline tests, and linked documentation/changelog; preserve legacy PIT types, identities, bundles, and observed persisted result bytes.
- Production validation: only the existing producer creates `SecObservedFinancialProduction`, using a private capability and integrity binding over the full request, evidence, vintage/ordered rows, UTC produced_at, and every output receipt field; constructor and selector revalidate the binding, rejecting direct fabrication and `dataclasses.replace` substitutions.
- Bind canonical result bytes to output response_sha256 and enforce exact SEC output request/serialization, output observation time = produced_at, matching request/filing/evidence/vintage identities, accepted_at <= source observation, and known_by_at <= produced_at; retain current parser/configuration identities. No loader, new persistence, replay I/O, or parser invocation in selection.
- Types: separate observed quality record, consumer commit, policy, and selection result; package production identity is a domain-separated digest of its path-free canonical output identity plus output observation identity, never a legacy normalized_version_id. Reuse only `SecQualityStatus` if useful. Paths remain private integrity inputs.
- Policy: require explicit output schema, parser version, configuration version/identity, quality policy version, consumer_dataset_identity (SHA-256), and aware knowledge cutoff; normalize UTC. Quality and commit cutoffs equal the same knowledge cutoff; no implicit latest defaults or separate future quality cutoff.
- Quality: caller-attested records bind production identity, policy version, status, recorded_at, and optional supersedes ID with deterministic domain-separated identity. For each supplied production and selected quality policy, consider only records at/before cutoff; require recorded_at >= produced_at. Exact duplicates deduplicate; identity collisions fail.
- History: visible quality records form one chronological chain per production/policy: first PASS or QUARANTINED has no predecessor; every subsequent record supersedes the immediately prior record at a strictly later time. Missing/cross-production/cross-policy predecessors, forks, cycles, and distinct same-time records fail; REVOKED requires a predecessor. Future records do not revoke or invalidate a past chain.
- Commits: caller-attested records bind exact production, quality-record, consumer dataset identities and UTC committed_at with deterministic domain-separated identity. Visible commits for selected production/policy/dataset must reference a visible PASS record and satisfy committed_at >= quality.recorded_at >= produced_at; missing/wrong bindings and time violations fail. Future commits do not establish past eligibility.
- Selection: eligible production must match every version selector and known_by_at <= produced_at <= cutoff; choose the latest visible quality record, require PASS, then a commit referencing that exact record and requested dataset at/before cutoff. Later quarantine/revocation blocks prior commits; a later PASS requires its own commit. Missing quality/commit yields no result.
- Output: return complete package, selected quality, and latest matching commit for every eligible production, sorted deterministically by known_by_at, accession, production identity; deduplicate exact inputs and reject conflicting identities/ties. Empty input or no eligible packages returns an empty tuple; no accession-level latest/amendment collapse or row normalization.
- Bounds: consume iterables incrementally with hard caps of 100 productions, 10,000 quality records, 10,000 commits, and 100,000 aggregate production rows; caller limits, if exposed, are positive exact integers and stricter-only. Reject over-limit inputs explicitly before selection; production limits remain unchanged.
- Acceptance: denied-network synthetic real-producer tests cover cutoff equality, both observation orders, future history isolation, revocation/quarantine/re-pass, wrong dataset/policy/configuration, malformed chain/commit, duplicates/conflicts, tampered production fields/rows/receipts, caps including generators, deterministic order, and empty results; verify unchanged persisted observed bytes and legacy identities with focused regression evidence.
- Stop conditions: no consumer migration, network, live publication, old availability promotion, standalone durable replay, or generalized row version framework. Independent review of actual diff and current focused checks is required; consumer rerun evidence is not required because no consumer integration changes.
