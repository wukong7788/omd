# SEC neutral metric graph

1. Goal/files: add `metric_graph.py` with focused private models/evaluation helpers, synthetic tests, exports and coverage documentation after slice16. This is an offline bounded graph of named financial formulas, reusing `select_sec_financial_versions`, `SecPitMode`, `SecPitPolicy` and the existing four-quarter arithmetic/period contracts; no arbitrary expression evaluator, provider acquisition, FX conversion, issuer verification, strategy, publication or consumer write.
2. API: frozen `SecMetricGraphConfig(canonical_cik, declarations, steps, mode, knowledge_cutoff, policy, valuation_at, scope_reference)` derives configuration_identity; `compute_sec_metric_graph(*, config, versions, quality_records, consumer_commits=(), external_inputs=(), max_input_records=10000)` returns frozen `SecMetricGraphResult(config, terminals, steps, result_identity)`, whose final step is the requested output. `valuation_at` is an optional UTC datetime, required for any valuation formula. Canonical CIK is nonzero unpadded ASCII digits, at most10; source ownership and scope_reference remain caller assertions.
3. Terminal declarations: frozen `SecMetricTerminalDeclaration(local_id, source_kind, source_identity, metric, period_kind, fiscal_year, fiscal_end_quarter, period_start, period_end, native_concept, currency, accounting_scope, attribution_scope, dimension, comparability_cohort, security_basis, declaration_reference)`; source_kind is exactly NORMALIZED_FACT or EXTERNAL_ATTESTATION, source_identity lowercase SHA256. Metric is exactly REVENUE, NET_INCOME, OPERATING_INCOME, GROSS_PROFIT, CFO, CAPEX, COMPANY_MARKET_CAP, SECURITY_PRICE or FORECAST_EPS. Period_kind is exactly INDEPENDENT_QUARTER, YTD, FY, INSTANT or FORECAST; fiscal fields are required integers year1..9999/quarter1..4 for actual durations, otherwise absent. Duration/forecast dates are ordered; INSTANT has start=end. Security_basis is a nonempty caller identifier for equity/share-class/ADR/split basis; no ratio or share conversion is inferred.
4. SEC terminals: rerun the existing selector once over the aggregate bounded supplied records, then resolve each NORMALIZED_FACT identity to an eligible `SecPitResult`; retain its complete version/quality/optional commit records. Require exact declared concept, period dates/type, dimension, non-null complete row unit and currency agreement with the selected row; metric/period-kind/fiscal/scope/cohort/security declarations are explicit caller assertions, never inferred from dates/concept names. Reject missing selected IDs, null/nonfinite values, policy mismatch, duplicate terminal IDs or source identities and unexpected source-kind/metric combinations; SEC terminals support only actual financial metrics. Do not accept freely constructed prior derived-result values as terminal evidence.
5. External inputs: frozen `SecMetricExternalInput(external_id, metric, value, unit, currency, valuation_at, period_start, period_end, forecast_horizon, accounting_scope, attribution_scope, security_basis, company_total_equity, source_reference, source_available_at, observation_identity, observed_at, recorded_at, quality_reference, quality_recorded_at, commit_identity, committed_at)` is an explicitly caller-attested record; external_id is the SHA256 of all other canonical fields, never a caller-supplied authenticating seal. Allow only COMPANY_MARKET_CAP, SECURITY_PRICE and FORECAST_EPS; company_total_equity must be exactly True for company cap and False otherwise; require nonempty source/quality references, SHA256 observation identity, finite Decimal and UTC times, with optional commit identity/time present together. Market cap/price have instant dates matching valuation_at's UTC date; forecasts preserve ordered dates and nonempty horizon (e.g. FY1/NTM) and accounting basis. Terminal declarations must match every overlapping external field. These records do not create SEC PASS evidence or prove first publication; quality_reference is an attestation reference, not a validated quality history.
6. Availability: SEC eligibility and bounds preserve the existing mode semantics; MARKET_KNOWN uses source_available_at, SYSTEM_REPLAY additionally uses observation, record, quality and consumer-commit times and requires commits. External source_available_at must be <= knowledge_cutoff; quality_recorded_at must be <= policy.quality_cutoff, and SYSTEM_REPLAY additionally requires commit and all external observation/record/quality/commit times <= knowledge_cutoff. External times cannot precede source availability except observation may precede a separately attested later publication; require recorded_at >= observed_at and committed_at >= recorded_at/quality_recorded_at when present. Each terminal/step exposes the maximum applicable input availability bound only, never a recipe production timestamp. Valuation graphs require knowledge_cutoff <= valuation_at; actual financial period ends cannot exceed valuation_at's UTC date.
7. Graph shape: frozen `SecMetricStep(step_id, recipe, input_refs, domain_policy, capex_sign, division_precision, rounding)`; references name terminal IDs or earlier step IDs only, distinct in each step, with no duplicate IDs across terminals/steps. Reject forward references/cycles and unused terminal/step records; every supplied node must be an ancestor of the final step. `SecMetricRecipe` contains only FOUR_QUARTER_TTM_V1, FY_YTD_TTM_V1, CFO_CAPEX_V1, YOY_V1, MARGIN_V1, PE_V1, PS_V1 and FPE_V1; no arbitrary operators. Output metric/period/unit/scope/bound are derived by these fixed rules, not caller-written result metadata.
8. TTM formulas: FOUR_QUARTER_TTM_V1 takes four chronologically consecutive independently declared quarters of REVENUE or NET_INCOME, equal currency/unit/dimension/accounting/attribution/cohort/security basis, and reuses slice14's exact contiguous fiscal sequence validation without imposing calendar-year lengths. FY_YTD_TTM_V1 takes `(prior_fy,current_ytd,prior_ytd)` of the same REVENUE or NET_INCOME basis and returns prior_fy + current_ytd - prior_ytd; prior FY is fiscal quarter4, both YTDs have equal end-quarter1..3, current fiscal year=prior+1, prior_ytd starts with prior_fy and ends before it, current_ytd starts the day after prior_fy ends. Both TTM operators derive fiscal year/end-quarter from their chronologically latest input. FY bridge output period starts the day after prior_ytd ends and ends at current_ytd end, kind TTM; comparability of 52/53-week boundaries is explicitly asserted by shared cohort, not inferred as equal day counts.
9. CFO/CapEx and comparisons: CFO_CAPEX_V1 takes `(cfo,capex)` with exact matching actual duration kind/fiscal labels/dates/currency/unit/dimension/accounting/attribution/cohort/security basis; capex_sign is `SecMetricCapexSign` and must explicitly be POSITIVE_OUTFLOW (require CapEx>=0, subtract) or NEGATIVE_OUTFLOW (require CapEx<=0, add); declaration_reference defines included CapEx scope, with no default taxonomy expansion. Output metric FREE_CASH_FLOW retains period/basis. YOY_V1 takes `(current,prior)` of the same actual metric/basis (REVENUE, NET_INCOME, OPERATING_INCOME, GROSS_PROFIT, CFO, CAPEX or FREE_CASH_FLOW only), matching period kind/end-quarter and fiscal years exactly one apart, nonoverlapping ordered periods; computes (current-prior)/prior under POSITIVE_DENOMINATOR or (current-prior)/abs(prior) under ABS_NONZERO_DENOMINATOR, with explicit domain choice. MARGIN_V1 takes `(profit,revenue)` for NET_INCOME/OPERATING_INCOME/GROSS_PROFIT or FREE_CASH_FLOW numerator and REVENUE denominator, exact matching period/basis, and computes profit/revenue; negative numerator is permitted, denominator must be positive. Ratio unit is `pure`, not percent.
10. Valuation formulas: PE_V1 takes `(company_market_cap,ttm_net_income)` and PS_V1 `(company_market_cap,ttm_revenue)`; market cap must explicitly declare company-total equity scope and matching equity attribution/security basis, not a single-class substitute; denominators must be TTM step outputs. FPE_V1 takes `(security_price,forecast_eps)` with exactly matching security_basis, currency, accounting/attribution scope and external valuation_at==config.valuation_at, preserving forecast_horizon and dates with forecast end after valuation date. Require identical currencies without FX, monetary actual/cap units equal currency, price/EPS units exactly `currency + '/security'` (for example `USD/security`), with security_basis carrying the explicitly matching share-class/ADR/split basis, and nonnegative price/cap plus strictly positive denominators; zero/negative earnings never produce a valid PE/FPE. Output is `pure`; ratio outputs cannot feed any further operator, so rounded intermediates are never reused. No PE×EPS price inference, stock-count inference, ADR/split adjustment or forecast-as-actual substitution.
11. Domain/missing policy: `SecMetricDomainPolicy` is exactly RAISE_NONPOSITIVE, MISSING_NONPOSITIVE, RAISE_ZERO_ABS or MISSING_ZERO_ABS; ABS policies are allowed only for YOY_V1, nonpositive policies for all division recipes. Invalid denominators either raise ValueError or return value=None plus stable reason NONPOSITIVE_DENOMINATOR/ZERO_DENOMINATOR; the missing final result retains its originating step ID. Ratio outputs are terminal-only, so no downstream missing propagation is needed. Missing source coverage, schema/basis mismatch, wrong signs, nonfinite numbers and resource violations always raise, never become domain-missing values. Nondivision steps require domain_policy=None, division_precision=None, rounding=None; all except CFO_CAPEX require capex_sign=None. Division steps require explicit precision integer1..100 and rounding in the explicit `SecMetricRounding` enum containing all eight standard Decimal ROUND_* modes, no ambient context defaults.
12. Arithmetic: keep Decimal values exact for addition/subtraction; normalize signs without applying ambient-context rounding, bound each coefficient digit count, absolute exponent and adjusted exponent to10000, and bound common-scale intermediate span including carry to10000 before allocation. Division uses an isolated Decimal Context with caller precision/rounding and fixed sufficient exponent range for the bounded inputs; results and intermediate bounds are validated before serialization. No float conversion, implicit percentage scaling or silent overflow/underflow. All formula versions and rounding/domain/sign policies participate in configuration/result identities.
13. Identity/evidence: frozen terminal and step results expose local ID, value-or-None, unit/currency, metric/period/fiscal/basis metadata, input references, input_evidence_ids, input_availability_bound, missing reason/origins and derived identity; input_evidence_ids bind each step to its complete transitive source/observation/quality/commit lineage; terminal evidence retains the full SEC selected records or the full distinctly labeled external attestation. Graph result identity hashes schema-versioned canonical config, all terminal evidence identities, ordered step results and final ID. Use compact sorted strict JSON, explicit Decimal strings, UTC Z/date ISO encodings, exact keys, no arbitrary key coercion; identities must change for source observation, quality/commit reference, policy, scope, graph structure or rounding changes. Do not emit `SecQualityRecord`, consumer commits or claim artifact authenticity/financial correctness.
14. Resources/acceptance: at most64 declarations,32 steps,4 references per step,10000 aggregate supplied versions/quality/commit/external records before dedup and at most one sentinel, stricter injected record cap allowed; text <=1024 UTF8 bytes, canonical config <=65536 bytes, bool rejected for integers. Tests cover every formula, exact vs rounded arithmetic under hostile ambient context, 52/53-week/YTD overlap/cohort failures, CapEx signs, negative/zero denominator policies and missing-result reasons, dimensions/currency/equity/ADR/security/forecast mismatches, future inputs/quality/commits, graph forward/unused/duplicate failures, resource boundaries and deterministic changed-lineage identity. Inspect a synthetic multi-step FY+YTD->PE/PS result and preserve existing PIT/four-quarter/event compatibility; synthetic evidence is not issuer qualification.
15. Stop/coverage: stop if implementing requires choosing a CapEx taxonomy, accounting basis, negative-base convention, forecast horizon, equity scope, FX/calendar/security conversion, publication time or quality authority not explicitly supplied by these declarations/policies. Caller-selected policies resolve routine formula choices; no business-policy default or user question is needed. This slice implements declared neutral calculations with traced eligible SEC inputs and separately attested external inputs; representative real-issuer metric replay, external source validation, consumer integration and market-data/consensus acquisition remain unverified.
