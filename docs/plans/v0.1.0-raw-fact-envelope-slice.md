# v0.1.0 Slice 7 — Raw Fact Envelope and Row Revision Evidence

Status: **READY_FOR_EXECUTION**

Parent plan: [`v0.1.0-pit-market-facts.md`](v0.1.0-pit-market-facts.md)

## Objective

Add a provider-independent immutable envelope for one provider-native row that
composes the already accepted snapshot observation and availability contracts.
The envelope distinguishes the exact response-payload version from the
canonical content hash of one row and permits a row revision claim only after
an explicit same-key comparison with a prior envelope.

This completes the metadata contract needed by the P0 endpoint vertical slice
without changing endpoint fetch results, parsing arbitrary snapshot formats,
or defining consumer-normalized facts.

## Architectural Correction

`SnapshotRef.fact_version` and `SnapshotObservationRef.fact_version` identify
the exact combination of request identity, response payload hash, and
serialization identifier. They are response-level versions. A response-level
version can change because some other row changed, so it must not by itself be
called a revision of every row in that response.

The raw envelope therefore records both:

```text
fact_version              # exact response-payload version
row_payload_sha256        # canonical provider-native row content
```

and uses only an explicit same-primary-key comparison to classify the current
row relative to one prior row. With no supplied prior row, revision status is
`UNCLASSIFIED`; OMD does not claim that a key is globally first-seen from an
incomplete history.

### Revision status

```python
class RawFactRevisionStatus(str, Enum):
    UNCLASSIFIED = "UNCLASSIFIED"
    UNCHANGED_FROM_PREVIOUS = "UNCHANGED_FROM_PREVIOUS"
    REVISED_FROM_PREVIOUS = "REVISED_FROM_PREVIOUS"
```

### Built-in quality flags

```python
class RawFactQualityFlag(str, Enum):
    PIT_UNPROVEN = "PIT_UNPROVEN"
    DATE_ONLY_AVAILABILITY = "DATE_ONLY_AVAILABILITY"
    REVISION_UNCLASSIFIED = "REVISION_UNCLASSIFIED"
```

`PIT_UNPROVEN` is present unless `AvailabilityEvidence.pit_proven` is true.
`DATE_ONLY_AVAILABILITY` is present for date-precision source evidence.
`REVISION_UNCLASSIFIED` is present until a valid prior-row comparison is made.
Callers may add unique uppercase identifier-style quality strings, but may not
spoof or duplicate built-in flags.

## Envelope Contract

The immutable envelope exposes:

```text
observation                 SnapshotObservationRef
availability                AvailabilityEvidence
native_fields               immutable ordered provider-native row mapping
primary_key_fields          ordered native field names
entity_fields               ordered primary-key field names
native_schema_version       explicit caller/adapter schema identifier
adapter_version             explicit adapter identifier
row_payload_sha256          canonical row hash
revision_status             RawFactRevisionStatus
previous_fact_version       nullable response-version lineage
previous_row_payload_sha256 nullable row-hash lineage
quality_flags               computed built-ins plus caller flags
```

The following metadata are inspectable properties derived from the observation
rather than duplicated mutable inputs:

```text
provider
endpoint
request_identity
payload_hash       # observation.response_sha256
snapshot_id        # observation.snapshot_identity
fact_version
serialization_identifier
snapshot_fetched_at
```

Envelope schema version is the integer constant `1` exposed in `to_dict()`.

## Native Row and Hash Contract

`native_fields` is a copied, read-only mapping. Field order is retained for
inspection, while hashing uses sorted field names and compact UTF-8 JSON.
Allowed provider-native scalar values are:

- `None`, `bool`, `int`, `float`, and `str`;
- `date`;
- timezone-aware `datetime`.

Nested containers, bytes, naive datetimes, unsupported extension/numpy/pandas
objects, and secret-like field names fail explicitly. Provider adapters must
convert extension scalars to these lossless Python scalars before envelope
construction. Missing, zero, NaN, positive infinity, and negative infinity are
all preserved and receive distinct canonical encodings. Datetimes hash in UTC
but the immutable native mapping retains the supplied aware datetime value.

`row_payload_sha256` is lowercase SHA-256 of canonical compact sorted-key JSON.
Special values use explicit tagged forms so standard JSON's non-finite
extensions are never relied upon:

```text
NaN       -> {"__float__":"nan"}
+infinity -> {"__float__":"+inf"}
-infinity -> {"__float__":"-inf"}
date      -> {"__date__":"YYYY-MM-DD"}
datetime  -> {"__datetime__":"...Z"}
```

Primary and entity field lists must be non-empty, ordered, unique, present in
`native_fields`, and use non-null identity values. `entity_fields` must be a
subset of `primary_key_fields`. Non-finite float identity values are rejected.
No generic endpoint primary key is inferred by core.

## Observation and Availability Composition

The envelope constructor requires the observation and availability evidence to
refer to the same current fetch:

- exact provider and endpoint are taken from the observation;
- `availability.snapshot_fetched_at` must equal
  `observation.snapshot_fetched_at`;
- all existing observation/hash/UTC validation remains authoritative;
- identifiers and versions must be non-empty safe identifiers or lowercase
  SHA-256 values as applicable.

Add the preferred constructor:

```python
RawFactEnvelope.from_observation(
    store,
    observation,
    *,
    native_fields,
    primary_key_fields,
    entity_fields,
    native_schema_version,
    adapter_version,
    source_available_at=None,
    availability_basis=AvailabilityBasis.PROVIDER_FIRST_OBSERVED,
    availability_precision=AvailabilityPrecision.UNKNOWN,
    additional_quality_flags=(),
)
```

It must replay and validate the supplied observation through
`AvailabilityEvidence.from_observation`; tampered, mismatched, or backdated
observation evidence fails through existing public integrity errors. Core does
not parse the replay payload or prove row membership in arbitrary serialization
formats. Provider-specific adapters own extracting the native row from the
validated replay before constructing the envelope; this limitation is explicit
and prevents a false generic parser claim.

## Row Revision Classification

```python
current.classify_against(previous) -> RawFactEnvelope
```

returns a new immutable envelope. It requires:

- the same provider, endpoint, ordered primary-key field names and values;
- the same entity-field definition;
- the same native schema and adapter versions;
- previous `snapshot_fetched_at` not later than current;
- if row hashes differ, response `fact_version` must also differ.

Same row hash yields `UNCHANGED_FROM_PREVIOUS`; different row hash yields
`REVISED_FROM_PREVIOUS`. The returned envelope records the prior response
version and row hash. Classification cannot be chained against an unrelated
key, a future observation, or a representation/schema change. The original
envelopes remain unchanged.

This classification is relative only to the supplied prior envelope. It does
not claim exhaustive provider history or historical publication availability.

## Serialization and Defensive Behavior

`to_dict()` returns a fresh JSON-safe dictionary containing:

- encoded native fields with explicit special-value tags;
- primary/entity field lists;
- all derived observation identities/hashes/versions;
- availability via `AvailabilityEvidence.to_dict()`;
- revision lineage and quality flag strings;
- native schema, adapter, and envelope schema versions.

Mutating the source mapping, caller flag sequence, or returned dictionary must
not mutate the envelope. No credential, environment, filesystem path, payload
bytes, or consumer session is serialized.

## Non-goals and Stop Conditions

Do not:

- change endpoint fetch result types or automatically envelope DataFrames;
- add a universal scalar value/fact table or derived-fact contract;
- parse arbitrary snapshot serialization in core;
- infer provider primary keys, availability, first-seen-key, or consumer
  sessions;
- edit consumers, snapshots, availability behavior, dependencies, or versions;
- commit, push, publish, or call any live provider.

Stop with `EXECUTION_BLOCKED` if the frozen hash changes, correct
implementation requires modifying accepted snapshot/availability contracts,
row membership would need an invented generic parser, or overlapping edits
cannot be preserved.
