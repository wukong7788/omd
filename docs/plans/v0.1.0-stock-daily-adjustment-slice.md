# v0.1.0 Slice 1 — Typed Stock Daily and Adjustment Factor

Status: **READY_FOR_EXECUTION**

Parent plan: [`v0.1.0-pit-market-facts.md`](v0.1.0-pit-market-facts.md)

## Objective

Add typed, injected-client Tushare access to the provider-native A-share
`daily` and `adj_factor` endpoints. This slice supplies the two raw inputs
needed for later consumer-owned adjusted-return research without adding an
adjusted-stock-bars recipe or claiming PIT availability.

The concrete near-term caller is `funmoney_backtest` M2 stock transport. Its
normalization, adjustment method, date alignment, storage, and strategy
behavior remain outside OMD.

Official provider references reviewed on 2026-08-02:

- <https://tushare.pro/document/2?doc_id=27> (`daily`)
- <https://tushare.pro/document/2?doc_id=28> (`adj_factor`)

## Public API

Add and export:

```python
StockDailyRequest
StockAdjustmentRequest
TushareClient.fetch_stock_daily(request)
TushareClient.fetch_stock_adjustment(request)
```

Both methods return the existing defensive-copy `TushareFetchResult`. This
slice does not change the result or provenance models.

## Request Contract

Both requests require an explicit `EmptyPolicy` and support exactly one query
orientation:

1. one non-empty `ts_code`, optionally bounded by `start_date` and/or
   `end_date`; or
2. one exact `trade_date`, without a date range.

Dates use `YYYYMMDD`; reversed ranges fail before provider invocation. OMD does
not split or interpret comma-separated symbol lists in this slice. A supplied
`ts_code` is forwarded unchanged after non-empty validation.

The `fields` tuple is explicit, ordered, non-empty, and duplicate-free. Custom
fields are allowed, but `ts_code` and `trade_date` must be present because they
form the provider row identity.

### Stock daily defaults

Endpoint: `daily`

Default fields, in order:

```text
ts_code
trade_date
open
high
low
close
pre_close
change
pct_chg
vol
amount
```

Provider-native semantics are preserved:

- prices and `change` are provider values with no currency conversion;
- `pct_chg` is a percentage, not a decimal ratio;
- `pre_close` is the provider's ex-right previous close;
- `vol` is in hands (手);
- `amount` is in thousand yuan (千元);
- daily data is unadjusted;
- suspended days may be absent and must not be synthesized.

The documented optional `ah_vol` and `ah_amount` fields remain available only
through explicit custom fields; they are not default fields because their
history begins later and their absence must not alter the stable default
schema.

### Stock adjustment defaults

Endpoint: `adj_factor`

Default fields, in order:

```text
ts_code
trade_date
adj_factor
```

`adj_factor` is the provider-native factor. OMD does not normalize it, fill
missing values, join it to daily bars, infer factor availability, or calculate
front-/back-adjusted prices in this slice.

## Response and Failure Contract

For both endpoints:

- rows are stably sorted by `ts_code`, then `trade_date`;
- `(ts_code, trade_date)` must be non-null and unique;
- requested columns must all be present;
- empty results follow the caller's `EmptyPolicy`;
- provider non-DataFrame responses and malformed schemas raise
  `SchemaMismatchError`;
- duplicate keys raise `SchemaMismatchError`;
- a response containing exactly 6000 rows raises `PaginationError` as an
  ambiguous provider-cap boundary rather than silently accepting possible
  truncation;
- retry, permission, authentication, rate-limit, provenance, defensive-copy,
  and credential behavior remain the existing client contract.

No numeric value is imputed, scaled, coerced to zero, or rejected merely for
being null. This raw endpoint slice validates identity and structure; consumer
or future reviewed recipe contracts own numeric completeness requirements.

## PIT and Version Boundary

The official documentation describes normal update windows, but those
schedules do not prove exact historical availability. Therefore:

- `TushareFetchResult.provenance.retrieved_at` remains only the current fetch
  time;
- this slice does not populate `source_available_at`,
  `provider_first_observed_at`, `fact_version`, or `first_usable_session`;
- a current `adj_factor` response must not be represented as a historical
  vintage;
- snapshot-backed exact-version and first-observed contracts are implemented
  in a later frozen slice before OMD claims PIT-ready release completion.
