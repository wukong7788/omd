# v0.1.0 Slice 6 — Daily Basic Semantic Hardening

Status: **READY_FOR_EXECUTION**

Parent plan: [`v0.1.0-pit-market-facts.md`](v0.1.0-pit-market-facts.md)

## Objective

Harden the existing typed Tushare `daily_basic` transport contract so accepted
rows are within the caller's symbol/date scope and provider cap ambiguity is
explicit. Preserve all provider-native daily indicator values and missingness
without implementing funmoney's dividend-yield normalization, PIT session
alignment, or null interpretation.

Official provider reference reviewed on 2026-08-02:

- <https://tushare.pro/document/2?doc_id=32> (`daily_basic`)

The concrete `funmoney_backtest` caller currently consumes `ts_code`,
`trade_date`, and `dv_ttm`, then owns percent-to-decimal conversion,
next-session alignment, immutable dataset publication, and missing/non-finite
research semantics. Those transforms remain outside OMD.

## Public API

The public API remains:

```python
DailyBasicRequest
TushareClient.fetch_daily_basic(request)
```

No new result type, normalized fact, recipe, or availability field is added.

## Request Contract

Every request requires an explicit `EmptyPolicy` and exactly one orientation:

1. a non-empty `ts_code`, optionally bounded by `start_date`, `end_date`, or
   both; or
2. one exact `trade_date`, without either range boundary.

Dates are real calendar dates encoded as `YYYYMMDD`; malformed/impossible dates
and reversed two-sided ranges fail before provider invocation. A date boundary
without `ts_code`, a missing selector, whitespace-only symbol, or mixed exact
and range orientation also fails before invocation. A one-sided symbol range
is allowed because both provider boundaries are independently optional.

Default fields, in provider-documentation order:

```text
ts_code
trade_date
close
turnover_rate
turnover_rate_f
volume_ratio
pe
pe_ttm
pb
ps
ps_ttm
dv_ratio
dv_ttm
total_share
float_share
free_share
total_mv
circ_mv
```

The documented optional `limit_status` remains available through explicit
custom fields and is not added to the stable default schema. Custom fields are
ordered, non-empty, and duplicate-free, but both identity fields `ts_code` and
`trade_date` must be requested.

## Provider-Native Field Semantics

- `trade_date` is the provider observation date, not a proven publication
  timestamp or consumer session.
- `close` is the provider close value.
- `turnover_rate` and `turnover_rate_f` retain provider percentage semantics.
- `volume_ratio` retains the provider VOL/MA ratio.
- `pe`, `pe_ttm`, `pb`, `ps`, and `ps_ttm` retain provider ratios; documented
  loss-related PE nulls remain null.
- `dv_ratio` and `dv_ttm` are percentages, not decimal ratios.
- `total_share`, `float_share`, and `free_share` remain in ten-thousand-share
  units (万股/万).
- `total_mv` and `circ_mv` remain in ten-thousand yuan (万元).
- explicitly requested `limit_status` remains the provider integer status.
- null, NaN, positive/negative infinity, and zero remain distinguishable. OMD
  neither imputes them nor turns missing values into zero.

## Response, Identity, Scope, and Cap Contract

For every non-empty response:

- requested fields must all be present;
- `ts_code` and `trade_date` must be non-null;
- every `trade_date` must be a string, valid `YYYYMMDD` calendar date;
- a symbol-oriented response may contain only the requested `ts_code`;
- a supplied start bound is inclusive and no returned date may be earlier;
- a supplied end bound is inclusive and no returned date may be later;
- an exact-date response may contain only the requested `trade_date`;
- rows are sorted by `ts_code`, then `trade_date`;
- `(ts_code, trade_date)` is unique within one response; equal or differing
  duplicate values fail with `SchemaMismatchError`;
- exactly 6000 rows raises `PaginationError` because the provider documents
  6000 as the maximum response size and completeness is ambiguous at the cap;
- cross-fetch changes are revisions and remain distinct when persisted through
  immutable snapshot payload versions and observations.

An out-of-scope symbol/date or malformed response date raises
`SchemaMismatchError`. Missing columns, non-DataFrame responses, and absent
provider methods retain existing public schema errors. Empty responses follow
`EmptyPolicy`. No numeric completeness, finiteness, range, sign, or
cross-column formula is enforced by this raw transport.

## Availability Boundary

The provider documents a normal daily update window, but that schedule does
not prove exact historical publication times. Therefore this slice:

- does not map `trade_date` or the documented update window to
  `source_available_at`;
- does not infer `first_usable_session`;
- does not claim a current response is a historical vintage;
- does not choose a revision cutoff or revise consumer feature dates;
- retains `retrieved_at` only as current fetch provenance;
- relies on separately persisted snapshot observations when exact-payload
  first-observed evidence is required.

funmoney's current next-canonical-session rule and `/100` conversion remain
explicit consumer transforms, not SDK defaults.
