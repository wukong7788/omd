# v0.1.0 Slice 9 — PIT Fail-Closed Characterization Fixtures

Status: **READY_FOR_EXECUTION**

Parent plan: [`v0.1.0-pit-market-facts.md`](v0.1.0-pit-market-facts.md)

## Objective

Add one cohesive offline characterization matrix proving that the accepted
snapshot, availability, raw-fact, and endpoint contracts fail closed across
the P0 revision, late-arrival, missing-time, cutoff-boundary, replay,
partial-page, and historical-vintage risks.

This is an evidence slice. It adds no new production behavior. If the frozen
cases do not pass through the accepted public APIs, Luna must stop and return
`EXECUTION_BLOCKED`; it must not weaken an invariant or invent a consumer
policy to make a fixture pass.

## Fixture Matrix

Add `tests/characterization/test_pit_fail_closed.py` using only synthetic rows,
payloads, clocks, and temporary directories.

### 1. Revision and late arrival

Observe two different payloads for the same request at ordered fetch times.
Wrap same-primary-key provider-native rows whose economic/event date predates
both fetches. The later row may be classified as
`REVISED_FROM_PREVIOUS` only through explicit `classify_against(previous)`.
Both unclassified inputs remain unchanged, and the later row remains
`PIT_UNPROVEN`; the old event date must not backdate the observed version.

### 2. Missing announcement timestamp and date-only evidence

Wrap a row with a provider-native announcement date and pass that date as
`SOURCE_DECLARED` evidence with `DATE` precision. The envelope must contain
`DATE_ONLY_AVAILABILITY` and `PIT_UNPROVEN`. It must not serialize an invented
announcement timestamp, cutoff, or `first_usable_session`.

### 3. Consumer cutoff boundary remains outside OMD

Construct otherwise valid timestamp-precision source evidence immediately
before and immediately after a synthetic consumer cutoff. OMD may prove only
the supplied source timestamp; both serialized envelopes must omit cutoff,
calendar, dataset-commit, and usable-session decisions. The fixture must not
assert which trading session is usable. This negative boundary proves that OMD
does not silently choose a consumer cutoff rule.

### 4. Replay identity

Replay a real observation with its exact request and construct an envelope.
Replaying the same observation against a different expected `RequestSpec`
must raise the existing public integrity error. No later snapshot may be
substituted for the exact observation.

### 5. Partial-page and truncation failure

Use the typed `fund_adj` pagination transport with a synthetic provider:

- a full page followed by a short/empty terminal page completes with exact
  page count and stable rows;
- a still-full final authorized page raises `PaginationError` on
  `max_pages` exhaustion rather than returning partial data;
- a duplicate key across pages raises `PaginationError`.

Also reference, rather than duplicate, the accepted exact-cap tests for
non-pageable `daily`, `adj_factor`, `daily_basic`, and `fund_share` endpoints.

### 6. Current snapshot cannot prove historical vintage

Fetch a current payload containing an old provider-native date using
`PROVIDER_FIRST_OBSERVED`/`UNKNOWN` availability. The serialized fact must keep
the current observation timestamps, omit a source timestamp/session, and carry
`PIT_UNPROVEN`.

## Non-goals and Stop Conditions

Do not:

- implement or infer a trading calendar, cutoff, dataset commit, or
  `first_usable_session`;
- parse arbitrary snapshot payloads in core;
- add endpoint caps, pagination, deduplication, missing-value fills, or date
  policies beyond accepted contracts;
- edit production code to satisfy this evidence slice;
- edit consumers, commit, push, publish, or call a live provider.

Stop if a fixture requires a new public behavior, a production edit, a secret
or live call, or a changed frozen-contract hash.

## Acceptance

Sol accepts only after inspecting each fixture's actual evidence, the absence
of consumer-policy leakage, the existing cap-test references, the full offline
gate results, and built artifacts. Command success alone is insufficient.
