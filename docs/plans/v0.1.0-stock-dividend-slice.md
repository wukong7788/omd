# v0.1.0 Slice 4 — Typed Stock Dividend Events

Status: **READY_FOR_EXECUTION**

Parent plan: [`v0.1.0-pit-market-facts.md`](v0.1.0-pit-market-facts.md)

## Objective

Add typed, injected-client Tushare access to the provider-native A-share
`dividend` endpoint. This slice supplies raw stock dividend-event records for
the `funmoney_backtest` transport migration without choosing a strategy-usable
date, rebuilding `dv_ttm`, classifying an event as economically eligible, or
adding a dividend-yield recipe.

Official provider reference reviewed on 2026-08-02:

- <https://tushare.pro/document/2?doc_id=103> (`dividend`)

The concrete near-term caller currently preserves `end_date`, `ann_date`,
`div_proc`, `cash_div`, `cash_div_tax`, `record_date`, `ex_date`, `pay_date`,
and `imp_ann_date`. Its normalization, event eligibility, PIT cutoff,
historical revision handling, storage, and research behavior remain consumer
owned.

## Public API

Add and export:

```python
StockDividendRequest
TushareClient.fetch_stock_dividend(request)
```

The method returns the existing defensive-copy `TushareFetchResult`. This
slice does not change the result, provenance, availability, or snapshot
models.

## Request Contract

`StockDividendRequest` requires an explicit `EmptyPolicy` and accepts the five
provider selectors:

```text
ts_code
ann_date
record_date
ex_date
imp_ann_date
```

At least one selector is required. Multiple selectors are allowed and are
forwarded together; OMD must not replace the provider's conjunction semantics
with an exactly-one rule. `ts_code`, when supplied, must be a non-empty string
and is forwarded unchanged. Every date selector uses `YYYYMMDD`. Empty strings,
whitespace-only symbols, malformed dates, and a request with no selector fail
before provider invocation.

The `fields` tuple is explicit, ordered, non-empty, and duplicate-free. Custom
fields are allowed, but `ts_code` must be present because it is the only
documented universal entity identity in this endpoint contract.

Default fields, in provider-documentation order:

```text
ts_code
end_date
ann_date
div_proc
stk_div
stk_bo_rate
stk_co_rate
cash_div
cash_div_tax
record_date
ex_date
pay_date
div_listdate
imp_ann_date
base_date
base_share
```

Provider-native names, values, nulls, and units are preserved. In particular:

- `end_date` is the dividend reporting year/date role, not availability;
- `ann_date` is the proposal announcement date;
- `imp_ann_date` is the implementation announcement date;
- `record_date`, `ex_date`, `pay_date`, and `div_listdate` remain distinct;
- `div_proc` is the provider process state and is not mapped to an OMD enum;
- `stk_div`, `stk_bo_rate`, and `stk_co_rate` remain per-share ratios;
- `cash_div` and `cash_div_tax` remain provider values per share;
- `base_share` remains in ten-thousand shares (万股);
- null does not mean zero, no dividend, or an unimplemented event.

## Response, Revision, and Failure Contract

- requested columns must all be present;
- `ts_code` must be non-null;
- empty results follow the caller's `EmptyPolicy`;
- provider non-DataFrame responses and malformed schemas raise
  `SchemaMismatchError`;
- no composite row key is claimed in this slice;
- duplicate or near-duplicate rows are preserved, never silently removed;
- no row-count cap is invented because the reviewed provider document does
  not state one;
- rows are deterministically sorted by the ordered subset of requested default
  fields, beginning with entity and date/process roles and then value fields;
- retry, permission, authentication, rate-limit, provenance, defensive-copy,
  and credential behavior remain the existing client contract.

The absence of a uniqueness assertion is deliberate. Provider records may
represent different process states or later revisions for the same company
and reporting period. A future semantic manifest may add an append-version
identity only with evidence; this transport slice must not collapse history.

## Availability Boundary

Provider date fields do not establish a precise publication timestamp or a
consumer's first usable trading session:

- `ann_date` and `imp_ann_date` are date-only source roles;
- `record_date`, `ex_date`, and `pay_date` describe event mechanics, not when
  the record first became observable;
- `TushareFetchResult.provenance.retrieved_at` is only the current fetch time;
- snapshot-backed `provider_first_observed_at` may be represented separately
  by the existing observation ledger, but this endpoint fetch does not attach
  or infer it;
- a current response cannot prove what the provider returned historically.

OMD therefore does not populate availability evidence, select one date as
`source_available_at`, backdate a record, or expose a `first_usable_session` in
this slice.
