# SEC explicit event work and dependency invalidation

1. Goal/files: after discovery ledger slice 15, add `event_work.py`, a focused dependency-index module, shared private helpers only where needed, synthetic tests, exports and coverage docs. Deliver durable caller-reported work states plus an exact dependency invalidation planner together; no executor invocation, network request, daemon, scheduler, consumer write or financial calculation is part of this slice.
2. Existing evidence: accept `SecDiscoveryBatch` and replay it with `SecDiscoveryBatch.from_canonical_payload(..., store)` before journal initialization/restart. The selected event must occur in that rebuilt batch with the declared metadata digest. Reuse its event key and source observations, existing `fact_version`, normalized-version, quality-record and TTM-result identities; do not reinterpret an acceptance cursor or work state as availability/PASS/publication evidence.
3. Work identity/API: frozen `SecEventWorkSpec` fields are `event_key`, `metadata_digest`, nonempty `processing_version`, SHA-256 `configuration_identity`, sorted unique typed `input_version_ids`, and explicit integer `max_attempts` in 1..3. Hash its canonical schema-versioned payload to derive `work_identity`; processing/configuration/input changes create a different work identity, never reopen a terminal old work item. The input list may be empty for a discovery-triggered fetch; that does not assert that a later fetch has unchanged raw bytes.
4. Typed dependencies: frozen `SecDataVersionId(kind: SecDataVersionKind, identity)` accepts only `RAW_FACT`, `NORMALIZED_FACT`, `OBSERVED_PRODUCTION`, `DERIVED_METRIC`, `RECIPE_CONFIGURATION` and lowercase SHA-256 identities; kind participates in identity/equality. Frozen `SecDependencyEdge(input_version, output_version, canonical_cik, recipe_identity, recorded_at)` uses canonical CIK, a caller-supplied recipe/configuration identity and UTC time. These are declared lineage references, not verified artifact ownership or complete dependency coverage.
5. Commands: frozen `SecEventWorkCommand` fields are `command_id` (caller idempotency SHA-256), UTC `recorded_at`, `target_state`, optional `error_class` (`TRANSIENT`/`PERMANENT`), nonempty bounded `reason_code`, optional UTC `retry_at`, sorted unique `output_version_ids`, sorted unique SHA-256 `quality_evidence_ids`, and canonically sorted `dependency_edges`. Command identity hashes all fields including command_id; reusing command_id with different content is a conflict. No exception text, credentials, raw payloads, local paths or unbounded diagnostic logs are serialized.
6. State machine: `SecEventWorkPhase` is the enum and `SecEventWorkState` is the immutable state object; first command must target `DISCOVERED`; then allow only `DISCOVERED -> QUEUED`, `QUEUED -> FETCHING`, `FETCHING -> VALIDATING/RETRY_WAIT/FAILED`, `VALIDATING -> READY/QUARANTINED/FAILED`, and `RETRY_WAIT -> QUEUED`. READY, QUARANTINED and FAILED are terminal. Commands are explicit caller reports; the library executes no named activity and makes no assumption that an interrupted FETCHING operation safely completed.
7. Attempts/time: count total entries into FETCHING, initially zero, never exceeding spec.max_attempts. RETRY_WAIT requires TRANSIENT, an existing attempt, retry_at >= recorded_at and attempts remaining; leaving it requires the supplied command time >= retry_at. FAILED requires an explicit error class and forbids retry_at; permanent failures cannot enter RETRY_WAIT. All command times are nondecreasing and initialization cannot precede the maximum retained discovery-source observation time. No sleep, wall-clock read, timeout inference or automatic retry is performed.
8. State evidence: READY requires nonempty output_version_ids and quality_evidence_ids; these record the caller's readiness report and do not issue a `SecQualityRecord` or consumer commit. FETCHING -> VALIDATING requires nonempty output_version_ids. Other transitions forbid output/quality/dependency payloads except READY may repeat the same output set from VALIDATING and attach quality IDs/edges; READY must preserve that output set exactly. QUARANTINED records a reason without rewriting inputs. Error/retry fields are absent unless required by the applicable error transition.
9. Durable API: `SecEventWorkLedger(root, *, store).append(discovery_batch, spec, command, *, expected_receipt_id)` returns a frozen `SecEventWorkReceipt`; `.load()` returns `(head_receipt_or_none, work_state_or_none, registered_edges)`. One caller-selected root contains exactly one work identity and its original discovery batch. Exact already-committed command retries return their original receipt before stale-parent checks; conflicting command IDs, another work/batch, invalid transition or stale expected parent fail without advancing. `SecEventWorkState` fields are spec, discovery_batch_identity, state (SecEventWorkPhase), attempts, last_command_id, last_recorded_at, retry_at, output_version_ids and quality_evidence_ids, with derived state_identity. Receipt fields are generation, receipt_id, parent_receipt_id, work_identity, command_id, command_identity and state_identity.
10. Journal encoding/replay: reuse the existing POSIX directory-FD, no-follow, regular-file, flock, staging/rename/fsync and bounded canonical JSON helpers under a new `sec-event-work-ledger-v1` manifest schema, never write discovery-ledger generations. Exact manifest keys are schema, generation, parent_receipt_id, work_identity, discovery_batch, spec, command, state, registered_edges, receipt_id; embed original canonical discovery batch/spec, canonical command and rebuilt state/registered-edge set. Receipt identity hashes the complete manifest excluding receipt_id. Spec/command/state canonical dictionaries contain their named fields plus fixed schema labels sec-event-work-spec-v1/sec-event-work-command-v1/sec-event-work-state-v1 and omit their derived identities; typed IDs encode exactly kind/identity. Edges add schema sec-dependency-edge-v1; plan/index payloads use sec-event-invalidation-plan-v1/sec-dependency-index-v1. Use existing strict compact sorted UTF-8 canonical JSON and UTC Z timestamps throughout. Load replays the discovery batch with one operation-local source cache, then all transitions/edge registrations and compares reconstructed canonical manifests; unknown fields, gaps, duplicate commands, tampering and partial generations fail. No mutable head or material cleanup.
11. Edge registration: only READY registers edges, each output must be in its preserved output_version_ids, each input must be in spec.input_version_ids, CIK must match the rebuilt discovery event, and edge.recorded_at must equal command.recorded_at. Self-edges, conflicting exact edge identities and cycles fail before commit. Missing edges do not imply an input was unnecessary; caller-declared lineage completeness remains unproven. State records without new edges do not mutate a dependency graph.
12. Exact index/planner: `SecDependencyIndex(edges)` validates and builds adjacency once from bounded injected edges; `plan_sec_event_invalidation(index, changed_inputs, *, known_at)` returns frozen `SecEventInvalidationPlan(index_identity, changed_inputs, known_at, affected_outputs, traversed_edge_ids, plan_identity)`. Traverse only exact typed seed identities and edges with recorded_at <= known_at, transitively, deterministically, deduplicating paths. Unknown seeds yield no affected output for that seed; no issuer-wide scan, ticker match, date interpolation or inferred replacement ID. The plan marks existing output IDs for caller reconsideration; it never deletes/relabels past outputs, changes availability or substitutes current latest values in historical queries.
13. Resource contracts: at most 1,024 work generations, 16 MiB per manifest/128 MiB aggregate, 64 MiB distinct retained observation replay per operation, and existing depth/node/staging caps. Bound each work input/output/quality collection to 1,024 entries and changed-input seeds to 10,000 entries, commands to at most 10,000 edges cumulatively, and any combined index to 10,000 unique edges/20,000 nodes; count supplied records before deduplication and consume at most one sentinel beyond each cap. Every text field <=1,024 UTF-8 bytes; integer counters must reject bool; offer only stricter injected caps. Reject limits before graph traversal, persistence or large intermediate allocation, without truncation or claimed hard execution timeout.
14. Acceptance: synthetic offline tests cover complete state progression/restart, same/different exact retries, stale/concurrent writers, invalid jumps, permanent/transient retry gates, total-attempt exhaustion, out-of-order/early times, terminal immutability, unknown source event and hash-correct journal tampering. Cover exact DAG transitive/diamond paths, unknown seeds, cycles, conflicting registration, two issuers without cross-contamination, future edges excluded, unchanged inputs and configuration-version seeds. Exercise resource boundaries and source-cache reuse, inspect an on-disk restart artifact, and retain discovery-ledger/PIT/TTM compatibility tests.
15. Stop/coverage: stop for a need to infer execution success, financial quality, quarter/issuer ownership, source first-publication time, missing dependency membership, consumer publication or a destructive invalidation action. This is bounded work-report persistence and declared exact-dependency planning, not a functioning fetch/build service or a proven complete multi-provider dependency graph. Actual execution, scheduling, cancellation policy, reconciliation and consumer adoption remain explicitly caller-owned; no new user decision is required to implement these injected operations.
