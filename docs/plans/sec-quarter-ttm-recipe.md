# SEC four-quarter TTM recipe contract

1. Goal/gate: after the live-unit slice is committed, implement one offline issuer-level TTM sum for caller-selected revenue or net-income facts; this contract is design authorization, not implemented coverage or financial validation.
2. Files: a focused SEC quarter-TTM module and tests, SEC exports, README/CHANGELOG and the main plan's actual-coverage note; preserve existing identities, selector behavior, bundles and consumer repositories. Do not add providers, fetches, instrument mapping, storage services or scheduling.
3. Reuse/resources: inputs are existing normalized versions, quality records and consumer commits; invoke `select_sec_financial_versions` with explicit `SecPitMode`, `knowledge_cutoff` and `SecPitPolicy`. Its `SecPitResult` contains `version`, `quality_record`, and optional `consumer_commit`; retain mode/cutoff separately. Before selection, consume at most 10,000 records in aggregate across the three iterables, with at most one additional sentinel record to detect excess; reject excess without truncation. Keyword-only `max_input_records=10000` accepts only a positive non-bool integer at most 10,000 and permits a stricter caller cap. This bounds enumeration, not execution time of caller iterator methods or preexisting objects.
4. Selection: require exactly four distinct ordered `normalized_version_id` values in caller configuration and resolve each against the selector output. That selector returns all eligible versions, not a latest winner. Missing requested IDs, conflicting duplicate objects or ambiguous declarations fail explicitly; do not replace an input with another accession or silently return a partial sum.
5. Quarter declarations: configuration binds each selected ID to an explicitly declared independent fiscal quarter, its fiscal-year/quarter label, inclusive start/end dates, and a caller-supplied declaration/evidence reference. Require a consecutive four-quarter sequence and exact agreement with the row's non-null duration dates; reject cumulative YTD/FY declarations. Dates or a duration of roughly three months alone never prove an independent quarter. Every caller-supplied declaration/configuration text field is limited to 1,024 UTF-8 bytes, and its complete canonical recipe/declaration configuration to 65,536 UTF-8 bytes; validate before identity hashing, reject excess, and never truncate references.
6. Scope declarations: require explicit canonical CIK, metric name, permitted native concept for each input, accounting/attribution scope and a common comparability/revision cohort, with declaration references in configuration. Existing normalized versions do not expose a validated issuer field; these remain caller assertions, never verified issuer ownership, restatement compatibility or financial-scope evidence inferred from ticker or `standard_concept`.
7. Compatibility: retained rows must have finite non-null Decimal values, the declared concepts and dates, duration period type, identical non-null complete units and identical dimensions. Require contiguous nonoverlapping declared periods, including caller-declared 52/53-week fiscal boundaries; reject incompatible currency/scope declarations. No implicit FX, unit conversion, quarter derivation, or FY-plus-YTD bridge.
8. Formula/bounds: add the four Decimal values without float conversion or ambient Decimal-context rounding; preserve signs and the complete input unit. Before scaling/arithmetic, require each finite input's coefficient length at most 10,000 digits, absolute Decimal exponent at most 10,000, and absolute `adjusted()` at most 10,000. With `e=min(input exponents)` and `a=max(input adjusted())`, require `max(1, a-e+1)+1 <= 10000`, reserving one carry digit for four-term addition; reject excess before allocating powers of ten or expanded digit strings. Sum exact scaled integer coefficients and construct the result at exponent `e` without ambient-context rounding, including cancellation/zero. Support only the two named sum recipes with fixed initial recipe versions; caller configuration selects concepts and declarations, not arbitrary executable formulas.
9. Lineage: retain each selected version's normalized ID, content identity, observation/fact identity, quality-record ID and optional commit ID. Hash a canonical versioned result payload including ordered inputs, full declaration/configuration identity, recipe version, mode/cutoff/policy and output. Reuse existing raw/snapshot/version identities; introduce no parallel observation ledger.
10. Time semantics: retain all source, observation, production, quality and consumer-commit times from selected inputs. Report an input-availability bound: MARKET_KNOWN uses the maximum input `source_available_at`; SYSTEM_REPLAY uses the maximum of source availability, snapshot fetch, version `recorded_at`, quality `recorded_at` and selected commit time. The bound is not the derived recipe's publication or first usable session.
11. Eligibility: preserve all existing selector restrictions, including MARKET_KNOWN's rejection of automatic SGML acceptance-proxy versions and SYSTEM_REPLAY's quality-cutoff equality/commit gates. A caller-constructed `SecPitResult` alone is not sufficient proof: selection is rerun from supplied evidence. Do not upgrade observed-only products, infer publication from quarter dates, or fabricate derived quality PASS/consumer publication.
12. Output: an immutable recipe result carries declared issuer/metric/scope, aggregate period, Decimal value/unit, complete declarations, input evidence, query context and input-availability bound; distinguish caller declarations from validated structural compatibility in documentation. No claim of financial correctness, source authenticity or downstream PIT adoption follows from successful computation.
13. Acceptance: offline tests cover deterministic value/identity independent of ambient Decimal precision, valid fiscal-year rollover and 53-week declarations, rejected cumulative/absent quarter declarations, missing/duplicate versions, gaps/overlaps, null/unit/dimension/concept/scope conflicts, unavailable/revoked inputs and future quality/commit evidence. Cover exact/over record, text and arithmetic bounds, early termination of an excessive generator, stricter caller caps, cancellation and large exponents without unbounded allocation. Inspect an actual result artifact; do not mark real-data coverage from synthetic tests.
14. Compatibility/documentation: unchanged selectors and legacy identity/serialization tests remain valid; run focused tests and applicable static checks. Document the exact four-quarter-only coverage, caller assertions and exclusion of prices/estimates/ratios; consumers need separate adoption and rerun evidence before use.
15. Stop: stop for any need to guess issuer ownership, quarter-versus-YTD classification, comparability/revision scope, source publication or consumer commit; require caller declarations/evidence instead. No essential user choice blocks this policy-injected library slice, but unresolved real-data declarations block that data run.
