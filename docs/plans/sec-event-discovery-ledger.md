# SEC offline event discovery and atomic cursor ledger

1. Goal/gate/files: after the four-quarter TTM slice is committed, add an offline SEC submissions discovery module, a focused immutable ledger module, exports, synthetic tests and coverage documentation. This slice records discovered filings and cursor progress only; no daemon, polling CLI, provider download, task execution, consumer edits or publication is authorized by this contract.
2. Existing boundary: reuse `SnapshotStore`, `SnapshotObservationRef`, `SecPayloadReceipt.from_bytes`, `historical_basenames` and `historical_submission_url`. There is currently no `SecEdgarSubmissionsClient`; `SecEdgarSubmissionsRequest` requires known accessions and `resolve_submissions` may stop as soon as those accessions are found, so neither supplies discovery completeness. Keep those existing APIs and semantics unchanged.
3. APIs: expose frozen `SecDiscoveryPolicy`, `SecDiscoverySource`, `SecFilingDiscoveryEvent`, `SecDiscoveryBatch`, `SecDiscoveryCursor`, and `SecEventLedgerReceipt`; provide `discover_sec_filing_events(store, root_source, historical_sources, *, policy, prior_cursor)` and `SecEventDiscoveryLedger(root, *, store).append(batch, *, expected_receipt_id)` / `.load()`. Source values pair a canonical submissions URL with an existing observation; the library replays bounded bytes through the injected store, never invokes a network loader or reads credentials. Shared methods are `batch.to_canonical_payload()` and `SecDiscoveryBatch.from_canonical_payload(payload, store)`; the latter derives safe observation paths under `store.root`, replays sources, reruns discovery and rejects unequal rebuilt payloads.
4. Policy: require canonical zero-stripped CIK, explicit selected forms from `10-K`, `10-K/A`, `10-Q`, `10-Q/A`, `8-K`, `8-K/A`, UTC inclusive acceptance-window lower/upper bounds, an explicit nonnegative overlap duration, and mode `INCREMENTAL` or `RECONCILE` plus a nonempty policy version. An incremental window must include the prior cursor minus the declared overlap and extend through at least the prior cursor; reconciliation range/frequency remains caller-owned. No default number of overlap days, polling interval or promise that bounded overlap catches every late event.
5. Source closure: require one root URL `https://data.sec.gov/submissions/CIK{padded_cik}.json` and exactly the history URLs declared by that retained root, all bound to the same CIK through validated basenames; `filings.files` must be an explicit list, including an explicit empty list when no history exists. Replay root and every declared child, including pages apparently outside the selected window; validate required equal-length arrays, accession syntax, root/optional-child CIK and duplicate metadata. Reject missing/extra/duplicate sources, malformed reference lists, incompatible snapshot provider/endpoint/request CIK binding and conflicting duplicate accession rows before returning any batch. Root snapshots use endpoint `edgar_submissions`, no requested fields, and exactly either `{cik: padded_cik}` for an explicit discovery-only retained snapshot or `{cik: padded_cik, required_accessions: [...]}` for an existing lookup snapshot, whose accessions must be a nonempty sorted unique list of canonical accession strings. This additive retained-snapshot alternative does not relax `SecEdgarSubmissionsRequest` or claim a new download adapter; known-accession selection is not completeness evidence; historical snapshots use additive endpoint `edgar_submissions_history` with exactly padded `cik` and validated `basename` parameters and no fields. Snapshot integrity verifies retained correspondence, not SEC authenticity or an exhaustive real-time market universe.
6. Fields/classification: retain native accession, form, filing/report dates, acceptance text, primary document and optional `items` text; parsed acceptance must be an explicitly timezone-aware ISO timestamp normalized to UTC, with no timezone or date-only substitution. Preserve unknown optional values. Emit `SEC_FILING_ACCEPTED` for each selected in-window filing; additionally emit distinct `SEC_8K_ITEM_2_02` only for `8-K`/`8-K/A` with an exact `2.02` item token in a validated comma-separated item string. Missing/null items produce no earnings classification and remain explicitly unknown; an empty string remains explicitly empty and produces no earnings classification; an 8-K event is not a later 10-Q event or proof of the press release's first publication.
7. Event identity: SHA-256 of canonical schema-versioned JSON over provider `sec`, canonical CIK, accession and event kind; amendments have their own accession. Store native metadata plus a separate canonical metadata digest and every supporting observation/fact identity in the batch receipt. Equal event identities and equal metadata deduplicate across windows/restarts; conflicting metadata for a previously recorded event fails the append without changing history or cursor. Source correction adjudication is deferred rather than silently overwriting facts.
8. Discovery state: newly appended event keys have only `DISCOVERED` state in this slice. Repeated observations can append a new batch receipt without creating a second event; byte-identical batch retries return the original receipt. `QUEUED`, `FETCHING`, `VALIDATING`, `READY`, `QUARANTINED`, `RETRY_WAIT`, `FAILED`, delivery acknowledgements and derived-data watermarks require a later processing-state contract; cursor advancement does not mean an event was processed, financially validated or published.
9. Cursor semantics: maintain a per-policy/CIK cursor `(acceptance_at, accession)` ordered lexicographically, initially absent. Candidate cursor is the maximum of the prior cursor and all selected in-window filing pairs in the validated batch; empty batches leave it unchanged. Events at/below the cursor are still ingested and deduplicated when encountered. The cursor is an indexing aid, never source-publication evidence, MARKET_KNOWN qualification or a consumer commit; stable ledger policy identity hashes CIK, selected forms, overlap duration and policy version, while each batch separately hashes window bounds and incremental/reconcile mode. Changing stable policy identity requires a distinct ledger root.
10. Batch evidence: canonical batch identity includes policy/configuration, prior cursor, root and child observation/fact identities, normalized event metadata and candidate cursor. The factory issues a batch only after full source closure and schema validation; append/load must revalidate identities and cursor/event consistency rather than trust a caller-set `complete` flag. Completeness means this retained submissions root's declared page set only; delayed/unlisted SEC updates require caller reconciliation. Canonical batch dictionaries have exactly `schema_version` (integer 1), `policy`, `prior_cursor`, `sources`, `events`, `candidate_cursor`; exclude derived `batch_identity`. Hash UTF-8 JSON with `ensure_ascii=False`, sorted keys, compact separators and nonfinite values forbidden. Policy keys are `cik`, `forms` (sorted unique list), `acceptance_lower`, `acceptance_upper`, `overlap_microseconds` (non-bool integer), `mode`, `version`; cursor is null or exactly `acceptance_at`/`accession`. Timestamps use canonical UTC ISO text ending Z; dates/native optional metadata preserve documented types/null/empty distinctions without coercion. Sources are root first then history sorted by URL, each exactly `url` and `observation`; the descriptor includes all SnapshotObservationRef fields except path, with known mode and lowercase SHA-256 identities. Event keys are exactly `key`, `cik`, `accession`, `kind`, `form`, `filing_date`, `report_date`, `acceptance_native`, `acceptance_at`, `primary_document`, `items`, `metadata_digest`, `source_observation_identities`; sort events by key and supporting observation IDs lexically. Reject unknown/missing keys, duplicate JSON keys, wrong scalar/container types and noncanonical encodings on reload.
11. Atomic persistence: store immutable sequential generation directories containing one canonical manifest with newly discovered events, the full batch receipt, parent receipt ID and resulting cursor. Build a complete temporary directory, flush/fsync files, then atomically rename to the next fixed sequence name and fsync its parent; never replace an existing generation. The manifest commits events and cursor together, with no independently advancing mutable head. Expected-parent mismatch or a concurrent nonidentical winner fails; check an exact already-committed batch retry before parent mismatch and return its original receipt even if the head has advanced. `SecEventLedgerReceipt` fields are generation, receipt_id, parent_receipt_id, batch_identity, policy_identity, cursor, cumulative event_count and sorted new_event_ids; append returns this receipt, while load returns `(head_receipt_or_none, key_sorted_unique_events)`. The exact manifest keys are schema (fixed `sec-event-discovery-ledger-v1`), generation, parent_receipt_id, policy_identity, batch_identity, batch, new_event_ids, cursor, event_count, receipt_id; receipt ID hashes the same canonical JSON encoding excluding only receipt_id, and all redundant batch/cursor/dedup fields are rebuilt and compared. Caller supplies the root; no deletion, overwrite or automatic cleanup of material generations. On POSIX, traverse directories with directory descriptors and O_NOFOLLOW; serialize append with flock on a zero-byte regular `.writer.lock` file, never truncating an existing file. Under that lock, verify the next generation target does not exist before rename; an existing empty generation is corruption, not a replacement target. This coordinates library writers, not external mutation outside the ledger protocol.
12. Restart: `.load()` reads the contiguous committed generation chain, verifies schemas, hashes, sequence/parent links, event deduplication/conflicts and monotonic cursor derivation, and reconstructs receipt plus discovered-event index. Reject committed gaps, symlinks, malformed/partial committed files and tampering even with recomputed local file hashes when it conflicts with receipt/source identities; only exact library-owned hidden staging-directory names and `.writer.lock` are excluded from committed generations. Bound enumeration to 1,024 committed generations plus 1,024 owned stages and the one lock; reject unknown entries and excess rather than scan indefinitely. Resolve all retained source observations through the supplied store during validation, without hidden refetch; use a per-operation private cache keyed by the complete source descriptor (including URL), holding replay-validated immutable parsed content, and enforce a 64 MiB aggregate replayed-source budget for the entire operation, not a separate allowance per generation. Repeated identical descriptors reuse validated parsing; distinct observations count separately even if their bytes agree. The factory and rebuild helper accept a private `_replay_cache` shared by that operation only, never persisted or reused across calls; loss of a required observation fails explicitly.
13. Resources/errors: hard limits are 256 historical sources plus root, 8 MiB per replayed JSON source, 64 MiB aggregate source bytes, 100,000 aggregate filing rows, 10,000 emitted event keys per batch, 1,024 UTF-8 bytes per metadata/policy string, 16 MiB per generation manifest, 1,024 generations and 128 MiB aggregate committed manifest bytes during replay. Permit only stricter injected limits, validate before allocation/append, consume excess iterables with at most one sentinel, and fail rather than truncate. Parse both retained source JSON and ledger JSON with duplicate keys and nonfinite numbers rejected, maximum depth 64 and 500,000 nodes, checking bytes before decoding and depth/node budgets before constructing unbounded containers. Count all source filing rows before deduplication, stop before appending an event beyond its cap, and apply remaining aggregate source-byte allowance to each replay before decoding. Use stable discovery validation/coverage/conflict errors; injected iterator/store/file-system execution has no claimed hard timeout.
14. Acceptance: offline tests cover empty/complete history closure, missing/truncated/duplicate pages and column mismatch; exact 8-K item classification; same acceptance across accessions, amendments, overlap duplicates, late events below cursor, reconciliation, metadata conflict and missing timezone. Exercise source identity tampering, hash-correct ledger tampering, exact/over bounds, interrupted staging, post-rename restart, concurrent append collision, stale parent and exact retry; inspect persisted event/cursor equality after restart. Existing submissions lookup/snapshot tests must retain their behavior.
15. Stop/coverage: stop for unavailable complete retained page closure, guessed acceptance timezone or first-publication time, silent metadata correction, consumer processing/publication ownership, or bounds that require truncation. This is a partial P2 discovery/receipt slice, not the full event-processing state machine or late-event guarantee. No essential user choice blocks the injected library; concrete source snapshots, form/window/overlap policy and reconciliation scheduling must be explicitly supplied for a data run.
