# v0.2.1 — yfinance 1.7.0 Upgrade, QC-Gated Repair, and r10a0 Zero-Drift Audit Engine

Status: `PROPOSED`

## 1. Objective

Upgrade OMD's `yfinance` provider to `1.7.0`, implement a **QC-gated Targeted Repair architecture**, embed immutable provenance metadata, and establish an automated, reusable **Drift Audit Engine** (`ohmydata.tools.drift_audit` and `omd audit-drift`).

Verify **zero-drift** across 10+ years of historical data for the **`r10a0` ETF universe** (13 unique assets) under `repair=False`, while documenting and isolating the heuristic mutations introduced when `repair=True` is enabled.

## 2. Core Architecture Principle: `repair=False` as Canonical Baseline

### 2.1 Why `repair=True` Must NOT Be Global
1. **Heuristic Active Mutation**: `repair=True` is not a simple NaN cleaner; it actively modifies prices, reverses splits, recalculates dividend adjustments, and reconstructs daily bars from intraday tick data.
2. **False Repair Risks**: Known issues (e.g. GitHub #2924 in July 2026) demonstrated `repair=True` magnifying prices 100x and falsifying `Repaired?` flags.
3. **Silent Modification Without Audit Flag**: Official yfinance documentation states that "missing dividend adjustment" repair alters `Adj Close` without setting `Repaired? = True`.
4. **Clean US ETF Data**: Large-cap US ETFs (`SPY`, `QQQ`, etc.) already have clean Yahoo data; global `repair=True` introduces non-reproducibility and historical drift.

### 2.2 OMD QC & Targeted Candidate Repair Flow
OMD ingests raw data with:
```python
df = yf.download(
    symbols,
    start=start,
    end=end,
    auto_adjust=False,
    repair=False,
    actions=True,
    keepna=True,
)
```

Processing pipeline:
```
Yahoo Raw Data (repair=False)
       │
       ├── 1. OHLC Structure (Low <= Open/Close <= High)
       ├── 2. Suspicious Price Jump / Gap (|return| > threshold)
       ├── 3. Split Discontinuity Check
       ├── 4. Dividend / Adj Close Alignment (using actions=True)
       ├── 5. Session Coverage & NaN/Zero Volume Check
       │
       ▼ Anomaly Detected?
   ┌───┴───┐
   ▼       ▼
 [NO]    [YES]
   │       │
   │       ▼
   │    Query Targeted Repair Candidate (repair=True)
   │    Compare raw vs candidate
   │    Accept or Reject
   │       │
   ▼       ▼
Canonical Output (record raw_close, canonical_close, repair_status, repair_reason)
```

### 2.3 Provenance & Schema Specification
Canonical records retain full traceability:
- `raw_close`, `raw_adj_close`, `raw_volume`
- `canonical_close`, `canonical_adj_close`, `canonical_volume`
- `repair_status`: `PASS`, `SUSPICIOUS`, `REPAIRED`, `REJECTED`
- `repair_engine`: `None` or `"yfinance"`
- `repair_reason`: `None` or specific anomaly code
- `yfinance_version`: `"1.7.0"`
- `retrieved_at`: ISO timestamp

## 4. Reusable Drift Audit Engine (`ohmydata.tools.drift_audit`)

- **Calendar & Session Validation**: Strict date set alignment, missing/extra trading day detection, monotonic ordering.
- **Numeric Delta Auditing**:
  - `open`, `high`, `low`, `close`, `adj_close`, `volume`.
  - Max Absolute Error ($|v_{base} - v_{target}|$), Max Relative Error ($|v_{base} - v_{target}| / |v_{base}|$).
- **Zero-Drift Pass Gate**:
  - Under `repair=False`: Assert **0 row diff, 0 numeric diff ($0.0$)** across all 13 ETFs over 10+ years.
- **Reporting**:
  - Markdown summary table and per-symbol detailed mismatch log.
  - JSON machine-readable audit receipt for CI/CD integration.
- **CLI**:
  ```bash
  omd audit-drift --universe r10a0 --baseline-dir /path/to/1.5.1 --target-dir /path/to/1.7.0
  ```
