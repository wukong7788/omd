# v0.1.1 migration: ETF PCF endpoints

OMD 0.1.1 adds typed `etf_sh_cons` and `etf_sz_cons` requests and the
`fetch_etf_pcf_history` windowed recipe. Select the endpoint explicitly for the
exchange; their provider-native fields are intentionally different (`sca` for
Shanghai versus `sub_cc`/`red_cc` for Shenzhen).

Single calls fail closed on exactly 3000 rows. The history recipe retries by
deterministically bisecting inclusive calendar ranges and fails if one day is
still ambiguous. It preserves duplicates and provider-native values and
returns successful leaf provenance plus request/truncation counts.

Consumers remain responsible for exchange selection, trading-calendar lag,
availability timestamps, panel normalization, duplicate policy, storage, and
strategy use. `trade_date` alone is not point-in-time availability evidence.
