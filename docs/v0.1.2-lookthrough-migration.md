# v0.1.2 migration: snapshot-backed look-through source facts

OMD 0.1.2 adds the evidence boundary a look-through audit needs without
claiming historical point-in-time coverage. It provides deterministic
capture of validated Tushare results into immutable snapshots, typed
`stock_basic` and `index_member_all` endpoints, and pure recipes that report
observed ETF→index mappings, index-weight vintage audits, and manifest-only
source-fact bundles.

The field-by-field boundary against the funmoney look-through requirement
(`funmoney_backtest` commit `e783d9a0`,
`docs/plans/a_pit_data_contract_real_lookthrough_20260804.md`, SHA-256
`56dabb0c93f3160fa8585b324565d62da78f24f9b655a1c48378820f29644934`):

| Funmoney requirement | OMD 0.1.2 evidence | Consumer action |
|---|---|---|
| ETF→index mapping | observed mapping versions (`build_etf_index_mapping_observations`) | derive legal session only prospectively; historical gap remains blocked |
| `effective_date` | not available from current `etf_basic` | do not backfill; require a separate historical source |
| `first_usable_session` | availability anchor and observation time | map through canonical CN sessions and cutoff in funmoney |
| complete index vintage | retrieval/count/weight diagnostics (`audit_index_weight_vintage`) | accept only after consumer reviews authority basis |
| `weight_decimal` | named percent-to-decimal conversion (`percent_to_decimal_divide_100`) | retain native percent and conversion identity |
| industry | dated `index_member_all` facts plus observation evidence | select legal membership as of decision date |
| style/cluster | not provider-native | derive under a versioned funmoney method or remain blocked |

OMD 0.1.2 does not by itself make the existing historical B6 look-through
audit pass. A later funmoney change may consume this release only after
reviewing these semantic differences and pinning the immutable version.

## What is new

- `capture_tushare_result(store, request, result, *, observed_at)` writes the
  provider-native frame deterministically into an append-only
  `SnapshotStore`, revalidates replay, and returns an immutable
  `TushareObservedResult` with provenance, snapshot/observation/fact
  identities, availability evidence, and a content hash. `observed_at` must
  be explicit and timezone-aware; the capture path never reads credentials
  or calls a provider.
- `StockBasicRequest` / `fetch_stock_basic`: official selectors
  (`ts_code`, `name`, `market`, `list_status`, `exchange`, `is_hs`) with
  nonblank checks and documented value sets; a broad all-market request
  requires the explicit `all_market=True` opt-in. `ts_code` is required and
  non-null; duplicate `ts_code` fails closed; an exactly-6000-row response is
  rejected as the ambiguous documented cap. `industry` is current-observation
  metadata and never gains an inferred historical interval.
- `IndexMemberAllRequest` / `fetch_index_member_all`: official selectors
  (`l1_code`, `l2_code`, `l3_code`, `ts_code`, explicit `is_new`); at least
  one classification or stock selector is required. Provider-native dates
  (`in_date`/`out_date`) are validated, null `out_date` stays open-ended,
  exact duplicate rows are preserved, conflicting membership identities fail
  closed, rows outside the declared selectors are rejected, ordering is
  stable by `ts_code`, `in_date`, then industry codes, and an exactly-2000-row
  response is rejected as the documented cap. `complete_history=True` is a
  local contract flag that restricts a completeness claim to one explicit
  `ts_code`.
- `build_etf_index_mapping_observations` emits one observed mapping version
  per `(etf_symbol, observation_identity)` with statuses
  `CURRENT_OBSERVATION_ONLY`, `UNCHANGED_FROM_PREVIOUS`,
  `REVISED_FROM_PREVIOUS`, and `MISSING_INDEX_CODE`. It never emits
  `effective_date`, historical intervals, or `first_usable_session`; every
  row is `PIT_UNPROVEN`.
- `audit_index_weight_vintage` audits one captured exact-date vintage with
  native percent weights, an explicit decimal conversion identity
  (`percent_to_decimal_divide_100`), duplicate/null/non-finite/range
  diagnostics, native and decimal sums, caller-declared expected count with
  a nonblank basis, and a deterministic vintage identity. Retrieval
  completeness is `RETRIEVAL_COMPLETENESS_UNPROVEN` because the official
  `index_weight` contract documents no truncation/count guarantee; economic
  completeness is unproven unless retrieval and an auditable expected count
  both pass. Observed row count never becomes a source-declared expected
  count, and missing constituents are never treated as zero.
- `build_lookthrough_source_bundle` writes a manifest-only, new-or-empty
  output directory containing every input identity and content hash, per
  ETF/index/component statuses, explicit mapped indices without a captured
  weight vintage, missing index mappings, per-component industry coverage,
  and one top-level readiness value
  (`SOURCE_FACTS_COMPLETE`, `SOURCE_FACTS_PARTIAL`,
  `CURRENT_OBSERVATION_ONLY`, `BLOCKED_UNPROVEN_COMPLETENESS`). It never
  chooses a decision-date vintage, derives `first_usable_session`, fills
  missing industry, or generates style/cluster/overlap/exposure. Bundle
  identity is deterministic; `LookthroughSourceBundle.verify()` rejects
  tampering and overwrites.

## Semantic notes for consumers

- A newly observed old ETF record remains `PIT_UNPROVEN` for earlier decision
  dates; do not treat first observation as a historical effective date.
- `index_member_all` dates are provider-native membership dates, not
  publication times. Snapshot observation evidence is still mandatory for PIT
  use.
- `stock_basic.industry` is current metadata only; do not map it backward
  through history.
- Weight sum near 100% is necessary but not sufficient for economic
  completeness.
- Unsupported and missing index codes remain explicit in the bundle; do not
  fill them with `UNKNOWN` in a success table.
